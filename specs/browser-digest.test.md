# Browser Digest Test Specification

Map the browser-delivery contract to concrete tests.

Related spec: `specs/browser-digest.md`
Related plan: `docs/plans/2026-04-16-browser-readable-insight-delivery.md`

## Requirement Coverage Map

- `R1` canonical source -> `T1`, `T2`
- `R2` generated site root -> `T3`, `T4`
- `R3` publication boundary -> `T5`, `T6`
- `R4` date-scoped page content -> `T1`, `T7`
- `R5` source health visibility -> `T7`, `T8`
- `R6` archive and latest behavior -> `T4`, `T6`, `T9`
- `R7` semantic HTML and readability -> `T1`, `T10`
- `R8` asset stability -> `T11`
- `R9` atomic publication -> `T12`
- `R10` compatibility and preservation -> `T6`, `T11`, `T12`
- `R11` error handling -> `T2`, `T13`
- `R12` observability -> `T8`, `T9`, `T14`

## Unit and Integration Tests

### T1. Render one digest JSON into deterministic browser HTML

- Type: integration
- Fixture:
  - `examples/sample_digest.json`
- Verify:
  - HTML rendering reads canonical digest JSON only
  - the HTML contains the digest date
  - the HTML contains overview, top items, action-now, watchlist, and source summary sections
  - top items preserve bucket, source, confidence, relevance, why-it-matters, and recommended action

### T2. Rendering fails clearly when canonical JSON is missing or malformed

- Type: integration
- Fixture:
  - missing input file
  - malformed JSON
  - JSON missing required browser-contract fields
- Verify:
  - the command exits non-zero
  - the error is explicit
  - no misleading partial HTML file is left behind as the visible result

### T3. Publication writes into a dedicated site root rather than raw outputs

- Type: integration
- Fixture:
  - source root with one valid digest date
  - empty temporary site root
- Verify:
  - publish writes `index.html`, `latest/index.html`, and `YYYY-MM-DD/index.html` under the chosen site root
  - publish does not require serving or modifying raw `outputs/` directly

### T4. Published path contract matches the approved layout

- Type: integration
- Fixture:
  - site root after one publish
- Verify:
  - `site/index.html` exists
  - `site/latest/index.html` exists
  - `site/YYYY-MM-DD/index.html` exists
  - the date-specific page and latest page are both browser-readable entrypoints

### T5. `run` does not silently update the visible browser latest page

- Type: integration
- Fixture:
  - a pre-existing published site root
  - a new date-scoped digest generated by `run`
- Verify:
  - `run` may generate canonical outputs, but it does not change the visible `site/latest/index.html`
  - only the explicit publication command updates the visible latest/archive entrypoints

### T6. Publishing a later date updates latest while preserving older published pages

- Type: integration
- Fixture:
  - site root with one published date
  - a second valid digest date in the source root
- Verify:
  - older date page remains readable
  - newer date page is added
  - `latest/index.html` now reflects the later published date
  - archive index lists both dates in descending order

### T7. Browser page keeps degraded coverage explicit

- Type: integration
- Fixture:
  - digest JSON with zero bucket counts and degraded bucket-health statuses
- Verify:
  - bucket counts remain visible
  - bucket health remains visible
  - degraded coverage notes remain visible
  - degraded buckets are not omitted from the browser page

### T8. Browser page exposes source-summary observability without raw JSON

- Type: integration
- Fixture:
  - digest JSON with source failures, sparse-day notes, and mixed bucket states
- Verify:
  - a reader can see degraded states and source-summary details directly in the HTML
  - the page clearly identifies the digest date being viewed
  - when `top_items` exceeds collected `source_summary.total_items_seen`, the page explains that source summary reflects collected source coverage rather than expanded digest findings

### T9. Archive and latest pages show the expected published date relationship

- Type: integration
- Fixture:
  - site root after multiple publishes
- Verify:
  - archive page links to the published date pages
  - latest page clearly identifies the date it represents
  - degraded-but-successful published dates are handled according to the approved policy

### T10. Browser HTML is semantic and readable without JavaScript

- Type: integration
- Fixture:
  - rendered sample HTML
- Verify:
  - the page has a document title containing the date
  - the page has one primary heading
  - the page has a main content region
  - major digest sections are exposed as section headings
  - the page includes a viewport meta tag
  - no JavaScript is required for baseline reading

### T11. Historical published pages stay stable across later publishes

- Type: integration
- Fixture:
  - a site root with an already published older date
  - a later publish using the same template version
- Verify:
  - the older date page remains addressable
  - later publishes do not silently rewrite canonical historical `outputs/YYYY-MM-DD/` artifacts
  - if the implementation uses assets, historical pages do not break because of non-versioned asset replacement

### T12. Failed publish keeps the last-known-good visible site intact

- Type: integration
- Fixture:
  - pre-existing published site root
  - induced failure during staging or promotion
- Verify:
  - previously visible `site/index.html` and `site/latest/index.html` remain intact
  - readers are not exposed to a half-written page
  - a later successful publish can recover from canonical outputs

### T13. Missing canonical digest for the requested publish date fails cleanly

- Type: integration
- Fixture:
  - source root with no `digest.json` for the requested date
- Verify:
  - publish exits non-zero
  - visible site root is unchanged

### T14. Dedicated-machine browser smoke test proves real content, not only reachability

- Type: end-to-end
- Fixture:
  - a real generated digest on the dedicated machine
  - a published browser site root
- Verify:
  - local HTTP fetch of `latest/` returns content containing the expected digest date
  - the page contains the main digest headings
  - the page contains degraded coverage text when the chosen date is degraded

## What Not To Test

- dynamic app behavior such as sessions, authentication, or live database reads
- visual pixel-perfect styling beyond what the browser spec makes contractually visible
- external reverse-proxy implementation details beyond the documented static-serving boundary
- browser JavaScript behavior, because baseline reading must not depend on JavaScript

## Open Gaps

- None in the current contract. If later revisions add downloadable raw artifact links inside the generated site root, add explicit tests for those links without weakening the no-raw-outputs-serving boundary.
